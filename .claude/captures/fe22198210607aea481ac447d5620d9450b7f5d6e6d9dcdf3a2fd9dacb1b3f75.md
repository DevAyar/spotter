# Capture: Edit-before-Read failures after context compaction

## Pattern
Recurring `File has not been read yet` tool errors on Edit calls, observed
across three separate sessions (recorded ×6; the evidence array carries each
event twice — known watchdog duplication bug, flagged for its own phase).
Root shape: after context compaction/summarization the harness drops
file-read state, so the first Edit to a previously-read file is rejected
until the file is Read again in the fresh context. Cost is one retry each,
but the pattern recurs every compaction-heavy session and the fix is
procedural, not situational.

## Evidence
- 2026-07-02T14:26:02Z — Edit rejected: "File has not been read yet. Read it first before writing to it."
- 2026-07-04T16:46:35Z — Edit rejected: same signature, different session
- 2026-07-07T16:42:38Z — Edit rejected: same signature, third session

## Suggested response
One line added to the durable rules the SessionStart/PreCompact chain
re-injects via `compactPrompt` (`.claude/settings.json`): "After compaction,
Read the anchor region of a file before its first Edit — read-state does not
survive summarization." This is a directive-surface codification (hence
`lesson`), not a new artifact: the compactPrompt rules block already carries
the batching discipline; this appends one sentence to the same surface.
User applies it manually via a small-fix commit if approved.
