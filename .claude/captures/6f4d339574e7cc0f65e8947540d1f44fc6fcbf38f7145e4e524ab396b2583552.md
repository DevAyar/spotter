## Pattern
MISFIT: `agent-slicer` (`.claude/agents/05_meta/agent-slicer.md`) is typed
as a dispatchable Agent, but its own contract describes exactly the
single-known-file, mechanical-checklist shape that the manager's own
dispatch heuristic in `CLAUDE_MANAGER.md` says to handle by direct edit,
not dispatch — and that shape is precisely what `schema-verify-before-edit`
(a behavioral Skill honored without a hook) already covers for other
schema'd config files. This is a MISFIT, not an OVERLAP: no second live
artifact currently performs agent-slicer's job (schema-verify-before-edit's
own "Files watched" list does not include agent frontmatter), so there is
no duplicated-job pair to cite — the finding is that the *type* chosen for
this one job doesn't match its mechanics.

## Suggested response
Manual action: fold agent-slicer's job into a behavioral skill rather than
a dispatched agent. Smallest option: extend `schema-verify-before-edit`'s
"Files watched" list to include agent frontmatter, and lift agent-slicer's
already-written 4-field schema + safety rules (never invent new
frontmatter fields, preserve `model` unless asked, never rewrite whole
agents, confirm before touching a baseline/template agent) directly into
that skill's Rule/Notes sections. Alternative: a new sibling skill
(`agent-frontmatter-verify`) if keeping the checklist separate from the
config-file skill reads cleaner. Either way, retire `agent-slicer.md` as a
dispatchable Agent (or narrow its remaining scope to the "fixes mechanism
bugs in agent bodies" judgment work that doesn't reduce to a checklist,
if that slice is worth keeping separately) and update the Helper roster /
ROUTING.md rows accordingly. Any option is a user-directed edit — this
producer never edits artifacts.
